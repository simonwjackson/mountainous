## Decisions to preserve

- Keep proseQL as the store. Do not substitute SQLite, Markdown indexing, or direct app-owned turn files that bypass proseQL.
- Use pure Rust `proseql-native`. Rust behavior must match the TypeScript contract. Option A includes matching TypeScript changes and tests.
- Preserve turn IDs as `<meeting-id>.<NNNN>`, with no separate meeting field. Existing meeting IDs, speaker codes, content hashes, and query behavior must survive migration.
- Keep strict Prose parsing for database files. Preserve typed strings and per-source templates. Lenient parsing remains available for other consumers.
- Raw VTT files are temporary inputs, not an archive. The server holds them in memory. Successful or duplicate uploads delete the client input.
- Preserve ingest ordering: people and turns first, meeting record last. The meeting record makes retries duplicates. Current ingest removes orphan turns before retrying.
- Do not push or publish without permission. Classification with Jev is a separate, unstarted task. Do not return to API-key or topic-list questions now.

Per-file durability does not imply cross-file atomicity. Current native source writes use sorted durable replacements and quarantine after write failures. Partitioning must not promise a batch journal that does not exist. One-time migration adds risk because the deleted VTT inputs cannot reconstruct the archive.
