# User Guide Writing Prompt

Create a comprehensive, beginner-friendly user guide for [TOPIC].

## Guidelines

Follow these guidelines and is tailored specifically to how this feature works within our current application:

### Structure

1. Start with a clear, concise title using a # heading
2. Follow with a brief 2-3 sentence overview explaining what this guide covers
3. Include an "Overview" section listing key components/tools/concepts as they exist in our application
4. Organize content using hierarchical headings (##, ###)
5. Use numbered or bulleted lists for instructions and key points
6. Include code blocks with realistic, working examples that match our application's architecture
7. End with troubleshooting tips and best practices sections specific to our implementation

### Content Style

- Use conversational, plain language a junior developer can understand
- Explain WHY for each step or recommendation, not just HOW
- Define technical terms on first use, especially those unique to our application
- Break complex concepts into smaller, manageable chunks
- Include visual organization (lists, code blocks, headings) to improve readability
- Use concrete examples from our codebase rather than abstract explanations

### Code Examples

- Provide complete, working code snippets with proper syntax highlighting that follow our application's patterns
- Include comments explaining key parts
- Show both simple cases and at least one more complex/realistic example using our application's conventions
- Use naming conventions consistent with our existing codebase

### Must-Have Sections

1. What & Why - Explain the purpose and benefits within our application's context
2. Getting Started - Simple setup instructions specific to our environment
3. Basic Usage - Core functionality with examples showing integration with other application components
4. Advanced Features - More complex use cases relevant to our application's needs
5. Best Practices - Patterns to follow for success within our development workflow
6. Troubleshooting - Common issues and solutions specific to our implementation

### Formatting Guidelines

- Use markdown formatting throughout
- Where appropriate, add mermaid diagrams for flowcharts or sequence diagrams
- Highlight important notes or warnings about application-specific considerations
- Use backticks for inline code references
- Use triple backticks with language specifier for code blocks
- Use bold for emphasis on key terms or important points

### Tone and Style
Keep the overall tone helpful and supportive, acknowledging that readers may be new to this technology or to our application. Focus on building confidence through clear explanation and practical examples that directly relate to our codebase and architecture.
