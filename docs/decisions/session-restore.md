# Myoko window session restore

Myoko uses [hypr-session-restore](https://github.com/UpayanChatterjee/hypr-session-restore), pinned as a non-flake input. Its user service starts with `hyprland-session.target`, restores the last snapshot at graphical login, and saves every 60 seconds after a 90-second startup delay. The service also saves when it stops. Other hosts do not run it.

`modules/myoko-session-restore.nix` adapts the pinned script to Hyprland's Lua dispatch syntax and requires `hyprctl --instance 0`. It adds Ghostty's working-directory option, sets the snapshot directory to mode 0700 and the file to mode 0600, and does not overwrite a good snapshot with an empty one. This last change protects against shutdown racing with the save daemon. It splits Chromium's one-field process command into executable and flags. For Chromium app windows whose class matches the `--app=` URL, it saves `/run/current-system/sw/bin/web-app <url>` instead of replaying Chromium's internal process command. This is Myoko's existing launcher in `modules/web-apps.nix`; it gives Forgerie the correct app window class. To suppress the next restore, create `~/.local/state/hypr-session-restore/disabled`. Delete the snapshot to forget the saved windows.

This feature relaunches processes and puts their windows on saved workspaces. It does not restore unsaved edits, terminal scrollback, Chromium tabs, or Zed buffers; each application controls its own document and tab recovery. Tiled layout depends on Myoko's capacity and compaction rules, so exact positions are not promised. Multiple windows from one process and special workspaces are best effort. The snapshot includes process launch commands, which can contain sensitive arguments; do not publish the JSON file.

Before the first reboot, `scripts/test-myoko-session-restore-target` saved five real Myoko windows and checked the private snapshot permissions. Calling `restore` while those five windows were still open did not duplicate them. The Hyprland Lua launch dispatcher also accepted the script's `hl.dsp.exec_cmd` form. On the first generation-8 boot, Tailscale joined successfully, but only four of five saved windows returned: the Forgerie PWA failed to launch because its single-field command line was quoted as one executable. The five-window snapshot was preserved at `~/.local/state/hypr-session-restore/session.pre-gen8-20260925.json` before autosave could replace it. `scripts/test-myoko-session-restore-command` reproduces the bad launcher with the old script and passes with the tokenization fix. On the generation-9 one-time boot, Linux 7.2.7 and the original Tailscale identity returned, but the PWA was still missing. A second regular Chromium window was open at inspection, but the user opened it manually; it is not evidence of a restore failure mode. The five-window snapshot from before that boot is kept at `~/.local/state/hypr-session-restore/session.pre-gen9-20260925.json`. Launching the same URL through Myoko's `web-app` binary reopened the PWA with the correct class in the live session. On the generation-10 one-time boot, Linux 7.2.7 and the original Tailscale identity returned. The Forgerie PWA was present with its correct class at the first GUI check, without an agent launching it. The saved and open window class counts matched after the regular Chromium window appeared about two minutes after the restore service became active. Whether that Chromium window opened on its own or through a user action was not confirmed. The PWA and regular Chromium workspaces were swapped against the preboot snapshot; exact placement remains unverified. The private five-window snapshot from before this trial is `~/.local/state/hypr-session-restore/session.pre-gen10-20260925.json`. Generation 6 remains the EFI default. Do not use the saved snapshot as a substitute for saving work in applications.
