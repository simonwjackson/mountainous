# Phase 4, part 2: sounds and boot

Both themes have original UI sounds, an Interface sounds option, and original
Plymouth startup/shutdown packages. The installed boot screen is always
Platinum. The parent lands and deploys; this branch does neither.

## Sound ownership

`SoundEvents` carries semantic requests. `ThemeSounds`, referenced once at the
shell root, is the sole playback subscriber. Each theme's registry entry maps
its events to WAVs. The bank uses QtMultimedia `SoundEffect`, decoded PCM and
no per-event subprocess.

| Event | Hook | Platinum | Win98 |
|---|---|---|---|
| Menu open | Changed menu/screen in `MenuState.open` | Dry click | Start-menu click |
| Menu choose | Enabled leaf in `PlatinumCascadeMenu.choose` / `Win98Menu.trigger` | Higher click | Select click |
| Confirmation | Platinum alert creation; Win98 `shutdown`/`logoff` open | Alert beep | Exclamation |
| Notification | Fresh accepted upsert, never snapshot/reconnect replay | Two-note tag | Asterisk; Critical Stop for critical urgency |
| Minimize / restore | One per nonempty shared `WindowHider.run` batch | Down/up gesture | Down/up gesture |
| Available, no current caller | Registry `beep`, `emptyTrash` | Alert, dry trash-like rattle | Default Beep, Exclamation |

Native app menus/dialogs and compositor-only window changes are outside
Quickshell. There is no shell Empty Trash action to hook. Bulk hide/show plays
once, not once per moved window. A fresh replacement notification counts as
one event, as the notification owner's `fresh` contract specifies.

`desktop-theme sounds on|off|toggle|status` owns
`$XDG_STATE_HOME/mountainous/theme-sounds`, beside Extra dark. Missing/invalid
content means **on**; explicit `off` disables it. The same lock and atomic
rename protect writes. One global preference survives theme/mode changes.
`reapply` creates a missing file. Existing `status` output and `apply`
arguments remain compatible. Both pickers use this owner. Win98's checkbox
applies at once, independently of its Appearance draft/Apply button.

A blocking initial read prevents an off preference from briefly opening an
audio bank at startup. Off, a muted default PipeWire sink, or unavailable audio
destroys the bank, including playing sounds. Its PipeWire observer does not
open an audio output. Each effect has gain 1; the system output applies session
volume once. We never unmute or change that output. Errors stay silent, with
no replay queue that can produce late noises.

Qt's first output stream took 216 ms in the null-sink test before priming. The
enabled bank now primes each ready stream **muted**. Events during decode or
priming are ignored rather than delayed. Theme changes prime the new bank;
off/mute cancels it. Post-prime null-sink onset was below 30 ms (16–17 ms maximum
in the final pre-commit runs; timestamp precision is 1 ms). This does not prove
Myoko speaker, Bluetooth, WirePlumber route or hardware wake latency.

## Boot choice and safety

**Choice (a): fixed Platinum boot/shutdown, regardless of runtime theme.**
No privileged theme helper, session ESP writer, runtime `/boot` file,
early-boot state parser, or switch-time initrd rebuild is added. Cost: Win98
users see Platinum at boot/shutdown. Both original packages are installed for
preview. An administrator can select
`boot.plymouth.theme = "mountainous-win98"` in a later rebuild. The upstream
systemd-initrd module includes only the selected theme in the initrd.

Chicago95's general GPL-3.0+/MIT statement does not establish permission for
its visibly Microsoft-branded boot PNGs. Its script also references missing
`bullet.png` and `SpriteNew()`. We rejected these files rather than copying or
silently licensing them. Both packages use original art, the existing desktop
frame/palette, and the lock screen's original peak motif. Art/script:
**CC0-1.0**. Existing font inputs provide ChicagoFLF (Public Domain) and W95FA
Grid (SIL OFL 1.1); live password text keeps Plymouth's default DejaVu font.
Full source/licence notes: `modules/desktop-boot/README.md`.

No animation, sleep, progress wait or minimum display duration. Splash delay
is zero; `DeviceTimeout=0.1` replaces upstream's eight-second renderer wait.
Late graphics may fall back to text; fast readable disk unlock takes priority.
Password/question callbacks draw black live text separately below the art.
Long prompts scale to display width. Password bullets cap at 40 and never
expose the secret. Escape/text fallback remains upstream Plymouth behaviour.
No cryptsetup, password-agent, systemd-boot, kernel package, partition or LUKS
setting changes. Upstream Plymouth adds the `splash` kernel argument.

### Deploy gate: exact scope

Repository boot policy/art paths:

- `modules/desktop-boot.nix`
- `lib/desktop-boot.nix`
- `modules/desktop-boot/generate.py`
- `modules/desktop-boot/theme.script`

The README and `tests/desktop-boot.nix` do not change the running boot policy.
Upstream NixOS adds these initrd paths (Myoko uses systemd initrd):

- `/etc/plymouth/{plymouthd.conf,plymouthd.defaults,logo.png,plugins,themes,fonts}`
- `/etc/fonts/fonts.conf`
- `mountainous-platinum/{mountainous-platinum.plymouth,mountainous-platinum.script,boot.png,shutdown.png}` under the initrd themes store path
- Plymouth client/daemon, script/rendering libraries and their Nix closure;
  `systemd-tty-ask-password-agent`; udev `70-uaccess.rules`/`71-seat.rules`
- upstream initrd units `plymouth-{start,read-write,quit,quit-wait,halt,kexec,poweroff,reboot,switch-root,switch-root-initramfs}` and rescue/emergency quit hooks

Stage 2 gains `/etc/plymouth/{plymouthd.conf,plymouthd.defaults,logo.png,plugins,themes}`,
`/run/plymouth` links, upstream `plymouth-*` units and
`systemd-ask-password-plymouth.{path,service}`. Both theme directories live under
the store's `share/plymouth/themes/mountainous-{platinum,win98}`. A normal parent
rebuild writes a new initrd under `/boot/nixos/` and its normal systemd-boot
entry under `/boot/loader/entries/`; the entry gains `splash`. It does not
replace systemd-boot or the kernel with a different package. Evidence
`myoko-boot.json` records evaluated store paths and unit names. No session
command writes any of these paths.

## Checks and evidence

Evidence: `/tmp/tandem/phase4-sound-boot/`, served at
<http://100.114.19.92:8765/tandem/phase4-sound-boot/>. Its index plays every sound
and links both themes' picker and Plymouth captures. All Nix check builds run
through `/tmp/tandem/remote-check.sh` on Unzen/federation, never Zao.

| Focused check | Coverage |
|---|---|
| `desktop-sounds` | Recording sink per theme/event; off/mute/unavailable and teardown; actual menu open/choose hooks including disabled leaves; both real picker checkboxes through the packaged CLI/watcher; five appearances and narrow captures; all 15 production SoundEffects through a private PulseAudio null sink, PCM/onset assertions; deterministic regeneration; qmllint |
| `desktop-theme` | Default, saved sounds, invalid arguments, toggle, no-bus writes, preservation on theme/mode/reapply, atomic cleanup |
| `desktop-theme-shell` | Lifecycle/20 swaps/rollback; 27 picker geometry cases now covering sound-option focus reachability and label bounds |
| `desktop-boot` | Actual Nix-built QEMU boot with Plymouth; both production themes through guest Xvfb; startup/shutdown/password captures; systemd-ask-password → upstream Plymouth agent → typed `test-only` → requester, for both themes; script-error rejection; show-splash roundtrip must stay below 200 ms |

Pre-commit preview show-splash roundtrips were 45–73 ms, including test
transport. The QEMU fixture has no host GPU/seat. Sound tests have no real
`/dev/snd` or `/dev/dri`; the sink is private. The Myoko configuration evaluates
under the heavy guard. Ruff, ShellCheck (`-s bash` for nix-shell's shebang),
Python/Node syntax, Nixfmt and whitespace checks target changed files. Final
commit/check SHAs and logs are in the handoff. Earlier failed harness runs are
not final evidence.

### Not verified / review costs

No deployment, live session, real audio, physical reboot, encrypted test disk,
Bluetooth route or Myoko timing. The VM boots an unencrypted fixture; the live
systemd password protocol is tested, not cryptsetup unlocking storage. The
full boot-time delta on Myoko is not measured. Review the original boot art as
reuse of existing chrome, not Apple's Happy Mac or Microsoft's logo. Fixed
Platinum deliberately does not follow Win98 at boot. Win98's checkbox label
does not yet wrap below its existing picker minimum; it fits the tested 360 px
narrow screen. No full test suite ran.
